WCF to modern .NET, without breaking a single client

A .NET Framework 4.8 WCF service moved to ASP.NET Core on .NET 10. The real compiled legacy client was pointed at the new host by changing one address in its config file, and its output is identical, line for line. Generated from the repo's README results, golden files and source.

What was kept, and why

  

  
Kept in SOAPWhy

  
The RefrenceNo field name, typo includedClients generated code from it. Renaming it would silently send them nulls. REST uses reference.
GetConsignment returns null for an unknown number, while TrackConsignment raises a typed faultInconsistent, but clients have code paths written for each. REST returns a plain 404 for both.
Charging per started half kiloExisting invoices depend on it. A migration is the wrong moment to change a business rule.
Fault shapes, validation order and messagesClients may show or parse them.
Namespace, SOAP actions and basicHttpBindingThey are the contract.
